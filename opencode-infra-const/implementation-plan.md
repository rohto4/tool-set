# Implementation Plan — OpenCode-Link

> OpenCode（`anomalyco/opencode`）をフォークし、Codex ライクな GUI クライアントとして拡張する実装計画。
>
> **前提**: 既存コードベースの改修。ゼロ開発ではない。
> **フォーク元**: `https://github.com/anomalyco/opencode` (dev branch)
> **フレームワーク**: SolidJS + Tauri + @opencode-ai/sdk

## Phase 0 — フォーク + コードベース理解

**目標**: リポジトリをフォークし、既存コードの構造を理解する。開発環境を整備する。

| # | Task | 詳細 | 先行 | Est. |
|---|---|---|---|---|
| 0.1 | フォーク + クローン | `gh repo fork anomalyco/opencode --clone` → `dev` ブランチ確認 → アップストリーム remote 設定 | — | 0.5h |
| 0.2 | 開発環境構築 | Bun インストール → `bun install` → `bun dev serve` でサーバー起動確認 → `bun run --cwd packages/app dev` で Web UI 起動確認 | 0.1 | 1h |
| 0.3 | コードベース読解 | 以下のディレクトリを重点的に読む：`packages/app/src/`（ルーティング、ページ構成）→ `packages/ui/`（コンポーネント一覧）→ `packages/sdk/js/src/`（SDK API 全体像）→ `packages/desktop/`（Tauri 設定） | 0.2 | 3h |
| 0.4 | SDK API 全容調査 | `@opencode-ai/sdk` のエクスポート一覧を確認 → 使用可能な全メソッドを文書化 → 特に `session.*`, `config.*`, `app.agents()`, `event.subscribe()` の型定義を確認 → `opencode stats` 相当の API が存在するか調査 | 0.3 | 2h |
| 0.5 | Codex デザインリファレンス収集 | Codex Windows アプリのスクリーンショット取得 → UI 要素のリスト化（サイドバー、チャット、トップバー、設定画面） → 配色・タイポグラフィ・スペーシングの数値抽出 | — | 1.5h |

  │     │     │
  │     │     └── Phase 3 ─── サブエージェント管理
  │     │
  │     └── Phase 4 ─── 使用量分析（Phase 1 完了後、並行可）
  │
  └── Phase 5 ─── Phase 1〜4 の完了後（ただし 5.5 は全工程通して実施）

### 並行実装可能な組み合わせ

- **Phase 2 と Phase 4** は Phase 1 完了後、並行して進められる
- **Phase 0.3（コードベース読解）と 0.5（Codex リファレンス収集）** は並行可
- **Phase 5.5（ビジュアルポリッシュ）** は全工程を通して少しずつ実施

## リスクと対策

| リスク | 影響度 | 対策 |
|---|---|---|
| SolidJS の習熟度不足 | 中 | React と似ている部分も多い。1-2 日の学習期間を Phase 0.3 に含める。 |
| 既存コードの改修难度が高い | 中 | `packages/app` はモジュール化されている。ページ単位で改修可能。 |
| 使用量統計の API が存在しない | 中 | `opencode stats --format json` の CLI 呼び出しで fallback。 |
| アップストリームとの同期 | 低 | フォーク後の upstream merge は定期的に実施。変更量が少なければ conflict は最小限。 |
| Tauri v2 の Windows 固有バグ | 低 | 既存の `packages/desktop` で動作確認済み。 |
| Codex デザインの再現度 | 中 | Phase 0.5 でピクセル単位のリファレンスを収集。Phase 5.5 で追い込み。 |

## ゼロ開発との比較

| 項目 | ゼロ開発 | フォーク＋改修 |
|---|---|---|
| API 仕様追従 | 手動で OpenAPI スキーマを解析 | SDK が自動カバー |
| UI フレームワーク | React（新規） | SolidJS（既存、学習必要） |
| デスクトップシェル | Tauri（新規 scaffold） | Tauri（既存設定あり） |
| 認証・セッション管理 | 自前実装 | 既存実装を利用 |
| プロバイダ管理 | 自前実装 | 既存実装を利用 |
| エージェント管理 | 自前実装 | 既存実装を利用 |
| リスク | API 変更で壊れる | SDK が吸収 |
| **総合評価** | 高リスク・高工数 | **低リスク・同等工数** |
